# REA static security audit

**Target:** `/home/byron/projects/rea-review`, HEAD `1c2c2f1e78a74cdf5e4909ab8e775b090998a51f` (verified; working tree initially clean). Paths below are relative to that checkout.

**Disposition:** Conditional approval for a separately scoped, on-demand local CLI/stdio deployment—not approval to run the installer or auto-register all tools. No obvious credential-harvesting payload was identified in the inspected install/runtime paths. This is a static, targeted review, not proof that the entire repository or dependency graph is safe.

## Installation/deployment blockers and approval gates

1. **HIGH, conditional deployment blocker: unauthenticated wide-bound MCP.** HTTP is opt-in and defaults to loopback/ephemeral port (`src/config/mcpHttpEndpoint.ts:9-12`; `scripts/rea.mjs:15-23,66-71`). However, `MCP_HOST` or flags can select another host (`src/config/mcpHttpEndpoint.ts:34-44`); the request route checks Host/Origin only when a loopback allowlist exists and then dispatches directly to MCP, with no identity/authentication check (`src/server/http/serveStreamableHttp.ts:464-484`). Non-loopback deliberately relaxes these checks (`:533,565-568`). Given execution tools below, do not expose this listener to a LAN/public network without an independently authenticated, access-controlled boundary. Host/Origin checks are not user authentication. Local stdio avoids this listener entirely.

2. **MEDIUM, install supply-chain gap: this commit is not the artifact the installer selects.** Unspecified versions resolve GitHub's latest release (`install.sh:126-132`); installation runs global npm install, Linux under `$HOME/.local` (`:141-166`). The post-install check executes the installed binary and compares only its version string (`:167-170`), not source commit or independently approved artifact digest. A version pin alone does not establish equivalence to this audited tree, and the repository lockfile is not passed by this command. Block an unpinned installer/`@latest` deployment under a commit-reviewed approval; separately review/verify the actual distribution and dependency resolution. Registration is version-pinned but can still download via `npx -y` (`src/application/ClientRegistrationIdentity.ts:55-65`).

3. **MEDIUM, executable install hooks need explicit treatment.** Root lifecycle hooks are `prepack`, `prepare`, and `prepublishOnly` (`package.json:264-265,274`); no root preinstall/install/postinstall is declared. Source-checkout `prepare` imports and installs Husky if source and Husky exist, unless `HUSKY=0` (`scripts/prepare.mjs:7-27`). Hooks invoke lint-staged/checks (`.husky/pre-commit:1`; `.husky/pre-push:1`). Source `prepack` runs a build (`scripts/prepack.mjs:40-45`), not merely metadata inspection. Lockfile marks Frida plus development esbuild/fsevents install scripts (`package-lock.json:6355-6361,6694-6704,6717-6726,10752-10758`); Frida is optional and explicitly allowed (`package.json:397-402`). Dependency hook bodies/prebuilt native artifacts were not supplied or executed here. Gate those separately, or omit optional Frida/disable lifecycle scripts for an initial controlled install, accepting that capabilities/build steps may then require reviewed remediation. `allowScripts` is not itself evidence that every package-manager invocation enforces an execution policy.

4. **MEDIUM, scope gate: setup changes agent configuration and instructions.** Interactive setup requests consent (`src/cli/interactiveSetup.ts:54-68`) and separately offers Hopper (`:149-158`), but the installer launches setup by default when a terminal exists (`install.sh:21,173-175`); `--no-setup` disables it (`:92-94`). Hermes targets include its resolved home `config.yaml` and `skills` directory (`src/application/SupportedClients.ts:643-651`); setup selects skill installation alongside chosen clients (`src/application/Setup.ts:140-149`). Do not use broad setup as a substitute for an approved on-demand profile/tool configuration. Hopper setup can invoke root/package-manager operations through `pkexec` (`src/application/LinuxHopper.ts:640-647,689-719`). These are documented capabilities, not covert privilege escalation.

## Inherently powerful tools—not evidence of malicious installation

- **Host/process execution and injection:** process scenarios spawn a caller-selected executable, arguments and working directory (`src/process/capture/ProcessHarness.ts:280-306`); Frida can spawn/attach (`src/frida/FridaInstrumentationManager.ts:283-302`) and load inline or file-supplied code (`:395-399,449-461`; MCP entry `src/server/registerFridaTools.ts:115-136`). Rizin debugger commands accept caller input (`src/server/registerRizinDebugTools.ts:66-80`). The external-mutation admission helper manages session consistency, not human permission (`src/server/externalMutationAdmission.ts:13-33`). These require per-use approval/isolation, not blanket auto-approval.
- **Ambient credentials/permissions:** the generic provider launcher merges its host environment, defaulting to `process.env`, and passes it to children (`src/process/ProviderProcess.ts:247-251,282-289`). `shell:false` helps argument safety but does not sandbox the selected executable or remove credentials. Run on demand with a deliberately minimal environment, non-root identity, and constrained filesystem/network access. Upstream explicitly disclaims sandbox protection (`SECURITY.md:25-43`).
- **Network and data disclosure:** configured IDA MCP transports can launch commands or send tool arguments to a configured HTTP endpoint (`src/ida/IdaMcpConnection.ts:420-440,463-470`); browser CDP can attach to a selected endpoint (`src/browser/PlaywrightScenarioBrowser.ts:566`). Source-map retrieval is an outbound GET surface, but approves each redirect origin, omits credentials/referrers and bounds reads (`src/browser/WebSourceMapFetcher.ts:365-388,413-431`). Captures exclude common credential headers/cookies, not every possible secret: other text is retained unless explicitly declared sensitive (`src/browser/history/CaptureRedaction.ts:6-11,26-45,70-80`). Tool results delivered to an agent can therefore disclose proprietary source, URLs, body content or tokens to that agent's model provider. No live model call was made in this review.

## Positive controls, dependencies and licensing

- Private file modes are used in provider runtime/output paths (`src/ghidra/GhidraLauncher.ts:921,934`; `src/artifacts/SafeOutputTree.ts:111,209`). Hopper/Ghidra capability-token bridges are distinct from unauthenticated HTTP MCP; they are not a same-user sandbox (`SECURITY.md:27-36`).
- **Do not misreport Linux Hopper as SHA-1-only:** despite older wording in `SECURITY.md:50`, implementation checks length/SHA-1, then verifies a detached PGP signature against a pinned primary fingerprint before extraction, and checks launcher SHA-256 (`src/application/LinuxHopperPublisher.ts:207-215,255-290`). This documentation mismatch is low severity; the implementation has the stronger control.
- Runtime dependencies are exact-version declared, including MCP client/server, PTY, Playwright and optional native Frida (`package.json:321-361,397-402`); lock entries include registry URLs/integrities (e.g. `package-lock.json:6694-6697`). These are useful reproducibility controls, not a vulnerability scan. No claim is made about current advisory status or the safety of downloaded dependency code.
- REA declares MIT (`package.json:6`); third-party tools retain separate terms (`THIRD_PARTY_NOTICES.md:3-12`). Documented notice gaps affect clean-git-ref/minimisted and Frida (`:24-36`). Proprietary Hopper/IDA/JEB entitlement and automation/output restrictions require separate review (`:85-103`); not a blocker to using MIT REA with an appropriately licensed/static-only workflow. External GPL/LGPL components do not become MIT merely through integration (`:55-75`).
- REA is a reverse-engineering CLI/MCP toolkit, not itself a MiniMax agent-team orchestrator (`package.json:5`; `README.md:8,65`). Its shipped skill is generated from `.agents/skills/reverse-engineer-anything`; generation pins `@latest` references for the shipped manifest (`scripts/generate-skill-metadata.mjs:13-14,33-41`). Missing generated `skills/` in this source checkout is expected build output, not proof of a broken npm release.
